## 2. 是不是跑 `train_full_sft.sh`？

**不完全是。** `train_full_sft.sh` 只是官方提供的 **全参数 SFT（Full-SFT）** 启动器，是主线里的一条训练路线，不是整条主线本身。

主线完整闭环：

```text
① 从基座微调（LoRA 或 Full-SFT）
② 转成可加载的 HF checkpoint
③ 起 server → closed-loop 评测（clean + randomized）
④ 填 results.json → 写复现说明 → 打 Zip 提交
```

### 两条官方训练路线（二选一或都试）

| 路线 | 入口 | 特点 | 训完后 |
|------|------|------|--------|
| **LoRA（更轻、先试）** | Notebook §4：`/RoboTwin/RoboTwin_ROCm_Reproduction.ipynb` | `use_lora=true`，改动小、省显存/时间 | `scripts/merge_lora_dcp.py` → HF ckpt |
| **Full-SFT（你终端里看到的）** | `training/train_full_sft.sh` | `use_lora=false`，全参数更新，更重 | `scripts/convert_full_sft_dcp.py` → HF ckpt |

对应目录：

```text
/RoboTwin/experiments/lingbot_vla_v2_6b_robotwin/training/
├── train_full_sft.sh      # Full-SFT 启动脚本
└── lingbotvla_cli.yaml    # 训练配置（LoRA / Full 共用底稿）
```

**硬性规则（Notebook 原文）：**

- 竞赛/复现训练必须从 **基座** `robbyant_lingbot-vla-v2-6b` 开始  
- **禁止**从官方 `lingbot-vla-v2-6b-robotwin`（`global_step_50000`）接着训  
- 官方 robotwin ckpt 只适合当**对照评测**，不当训练起点  
- 训练数据：**仅 clean**；randomized **只能评测，不能训练**

### 怎么跑 Full-SFT（示例）

脚本默认 `GPU_COUNT=4`、`MAX_STEPS=100`（冒烟）。你机器是 **8 卡**，正式实验建议加长 steps：

```bash
source /opt/robotwin-env/bin/activate
cd /RoboTwin/experiments/lingbot_vla_v2_6b_robotwin/training

# 冒烟（确认能训）：10～100 steps
GPU_COUNT=8 MAX_STEPS=100 \
  OUTPUT_DIR=/workspace/runtime/outputs/full_sft_8gpu_100steps \
  bash train_full_sft.sh

# 正式实验：常见从 1000～5000 steps 起，再靠 closed-loop 选 ckpt
GPU_COUNT=8 MAX_STEPS=5000 SAVE_STEPS=1000 \
  OUTPUT_DIR=/workspace/runtime/outputs/full_sft_8gpu_5000steps \
  bash train_full_sft.sh
```

训完转换（Full-SFT，不是 merge LoRA）：

```bash
/opt/robotwin-env/bin/python \
  /RoboTwin/experiments/lingbot_vla_v2_6b_robotwin/scripts/convert_full_sft_dcp.py \
  --checkpoint /workspace/runtime/outputs/full_sft_8gpu_5000steps/checkpoints/global_step_XXXX \
  --training-output /workspace/runtime/outputs/full_sft_8gpu_5000steps \
  --output /workspace/runtime/outputs/full_sft_8gpu_5000steps/merged_checkpoint/global_step_XXXX/hf_ckpt
```

LoRA 路线请直接跟 Notebook §4（同目录下没有单独的 `train_lora.sh`，命令写在 notebook cell 里）。

## 4. 自研微调可以从哪入手？

按「投入小 → 大」排序，建议：

### A. 先跑通官方训练闭环（必做）

1. LoRA 或 Full-SFT **短 steps 冒烟**（确认 loss、落盘、转换、起 server）  
2. 单任务 `adjust_bottle` × 少量 episode，对比「基座 / 官方 robotwin ckpt / 你的 ckpt」  
3. 再拉长 steps，做小规模 clean 评测选点  

### B. 超参（最常见涨点区）

改 `train_full_sft.sh` 环境变量，或改 / 覆盖 `lingbotvla_cli.yaml`：

| 旋钮 | 位置 | 思路 |
|------|------|------|
| `MAX_STEPS` / `SAVE_STEPS` | 脚本 env | 冒烟 100 → 实验 1k～5k+；多存几个 step 做评测选优 |
| `lr` / `lr_min` / warmup | yaml `train.*` | 过拟合或不动时优先动学习率 |
| `GLOBAL_BATCH_SIZE` / micro-batch | 脚本 | Full-SFT 默认 global 256；需整除 `GPU×micro` |
| LoRA `rank` / `alpha` / `lora_scope` | yaml | 只训 action expert vs 更大范围 |
| `TEACHER_MODE` | Full-SFT：`full` / `current_depth` / `none` | 官方推荐 **`full`**；`none` 仅作对照，质量通常更差 |
| `image_augment` | yaml `data.image_augment` | 默认 `false`；可试轻量增强（仍只用 clean） |

### C. 数据侧（规则内）

- 必须：50 任务 × 每任务 50 条 **clean**（现成 lerobot 已齐）  
- 可试：任务子集先过拟合难任务，再全量；或调整采样比例（改 data list / sampler，需改代码）  
- 禁止：randomized 数据训练  

### D. 推理 / 评测侧

- 同一 ckpt 下调评测长度、是否 `expert_check`、planner（本机为 **MPLib**）  
- 全量前先用难任务子集验证，避免一上来烧十几小时  

### E. 结构改动（成本高，后做）

源码在：

```text
/RoboTwin/experiments/lingbot_vla_v2_6b_robotwin/source/lingbot-vla-v2
```

有改动必须写进提交材料 `04_复现与调优说明/reproduction_report.md`。

### 不建议当成「自研捷径」的

- 拿官方 `global_step_50000` robotwin ckpt **继续训**再交（违规风险）  
- 把 20G+ 权重复制进 `/workspace`（PVC 只有 100G）  
- 默认 `MAX_STEPS=100` 就当正式模型

## 5. 评测与 `results.json`：要不要现在全量跑？

| 阶段 | 评测规模 | 何时做 |
|------|----------|--------|
| 冒烟 | 1 任务 × ~10 ep | 链路验证（你已做过） |
| 调参选点 | 若干难任务 × 少量 ep | 每次训完 |
| **提交填分** | clean + randomized，约 50 任务 × 每 setting 足够 attempts | **最终 ckpt 定稿后** |

平台 Notebook 的「100 任务 × 10 ep」全量约 **15～19 小时（4/8 卡）**，入口：

```text
/RoboTwin/experiments/lingbot_vla_v2_6b_robotwin/scripts/run_clean_benchmark.py
```

提交目录：

```text
/workspace/Lingbo_VLA/梯度不爆炸小组_初赛提交材料/01_评测结果/results.json
```

当前仍是全 0；把最终跑出来的 `attempts` / `successes` 填进去。官方模板要求 clean / randomized 各任务 attempts 对齐赛事说明（常见按 **100** 填；若你实际跑的是 10，就按真实 attempts 填并在复现说明写清）。
